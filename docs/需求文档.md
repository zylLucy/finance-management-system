# 日常记账理财管理系统——需求文档

> **项目定位**：面向个人用户的日常记账理财管理系统，采用前后端分离架构（Vue 3 + FastAPI），以 MySQL 为核心数据库，集成大模型（AI）能力实现智能财务分析。

---

## 1. 项目概述

### 1.1 项目背景

随着消费场景日益多元化，个人财务管理变得愈发复杂。大学生及职场新人群体普遍面临收入来源多样（生活费、兼职、奖学金等）、消费渠道分散（外卖、网购、娱乐等）的问题，缺乏系统化的记账工具来追踪收支、控制预算。本项目旨在构建一款轻量级、智能化的日常记账理财管理系统，帮助用户建立健康的消费习惯。

### 1.2 项目目标

1. 提供便捷的日常记账功能，支持收入/支出记录的增删改查。
2. 通过可视化图表直观展示消费结构与收支趋势。
3. 支持月度预算管理，帮助用户控制开支。
4. 集成大模型（AI）能力，自动生成月度/年度财务分析报告。
5. 支持多用户画像，系统可适配不同消费习惯的用户群体。

### 1.3 技术架构

| 层级 | 技术选型 |
|------|----------|
| 前端 | Vue 3 + Vite + Element Plus + ECharts |
| 后端 | Python + FastAPI + SQLAlchemy ORM |
| 数据库 | MySQL 9.x |
| AI 服务 | DeepSeek / OpenAI 大模型 API |
| 认证 | Token 机制 + bcrypt 密码哈希 |

## 2. 用户角色与画像

### 2.1 目标用户

本系统面向有个人财务管理需求的用户，典型用户画像包括：

| 用户画像 | 特征描述 | 月收入 | 消费特点 |
|----------|----------|--------|----------|
| 实习打工族 | 有稳定实习收入，消费理性 | 3000-4000 元 | 餐饮为主，少量娱乐 |
| 数码游戏男孩 | 有家教兼职收入，爱好游戏数码 | 2500-3500 元 | 游戏充值、数码产品 |
| 高收入实习白领 | 实习薪资较高，社交活跃 | 5000-7000 元 | 餐饮社交、购物 |
| 时尚美妆女孩 | 注重穿搭美妆，有兼职收入 | 3000-4500 元 | 服饰美妆、外卖 |

### 2.2 用户权限

- **普通用户**：注册登录后，管理个人账单、预算，查看统计图表和 AI 报告。
- **系统隔离**：基于 Token 实现用户会话隔离，A 用户无法访问 B 用户的任何数据。

## 3. 功能需求

### 3.1 用户登录及验证

#### 3.1.1 用户注册

- **输入**：用户名（全局唯一）、密码
- **校验**：后端校验用户名是否已存在，若存在返回错误提示
- **安全**：密码使用 bcrypt 加盐哈希后存储，数据库不保存明文密码
- **反馈**：注册成功后跳转至登录页

#### 3.1.2 用户登录

- **输入**：用户名、密码
- **验证**：后端查询用户记录，使用 bcrypt 比对密码哈希
- **Token**：验证成功后生成 Token，前端缓存至本地，后续请求携带 Token
- **会话隔离**：确保用户只能访问自己的数据

#### 3.1.3 个人财务信息设置

- **月度预算设置**：用户可为每个月份设置预算金额（如 3000.00 元）
- **约束**：同一用户同一月份仅允许存在一条预算记录
- **修改**：支持随时修改当月及历史月份的预算

---

### 3.2 首页仪表盘

#### 3.2.1 核心数据看板

首页实时展示四项核心财务指标：

| 指标 | 说明 |
|------|------|
| 当日总收入 | 当天所有收入记录金额之和 |
| 当日总支出 | 当天所有支出记录金额之和 |
| 本月总消费额 | 当月所有支出记录金额之和 |
| 当月预算剩余 | 月度预算 - 本月总消费额，以百分比和金额展示 |

#### 3.2.2 年月选择器

- 首页顶部提供年月选择器，用户可切换查看任意历史月份的数据
- 切换月份后，看板数据、图表、预算信息同步刷新

#### 3.2.3 消费结构饼图

- 按支出分类（餐饮、购物、娱乐、交通、学习）聚合当月数据
- 以 ECharts 饼图展示各分类支出占总支出的百分比
- 支持鼠标悬停查看具体金额

#### 3.2.4 收支趋势折线图

- 按日期聚合当月每日的收入与支出金额
- 以 ECharts 双折线图展示，横轴为日期（1-31 日），纵轴为金额
- 直观反映月度收支波动趋势

### 3.3 收支分类管理

#### 3.3.1 预设分类

系统预设 9 种收支分类：

| 类型 | 分类名称 | 分类 ID |
|------|----------|----------|
| 支出 | 餐饮 | 1 |
| 支出 | 购物 | 2 |
| 支出 | 娱乐 | 3 |
| 支出 | 交通 | 4 |
| 支出 | 学习 | 5 |
| 收入 | 工资 | 6 |
| 收入 | 奖学金 | 7 |
| 收入 | 生活费 | 8 |
| 收入 | 兼职收入 | 9 |

#### 3.3.2 分类管理规则

- 分类为系统预设，用户不可自行新增或删除分类
- 删除分类时采用 `RESTRICT` 策略：若该分类下存在历史账单，拒绝删除

---

### 3.4 账单管理

#### 3.4.1 账单列表展示

- 默认显示当月所有账单记录
- 按日期降序排列（最新记录在前）
- 每条记录显示：日期、分类名称、金额、备注、收支类型
- 支持按日期范围筛选、按分类筛选、按备注关键词模糊搜索

#### 3.4.2 添加记账记录

- 用户填写表单：收支类型（收入/支出）、分类、金额、日期、备注（可选，255 字以内）
- 金额精确到小数点后两位
- 日期支持选择历史日期
- 提交后列表自动刷新

#### 3.4.3 修改记账记录

- 在账单列表中直接编辑单条记录
- 支持修改金额、分类、日期、备注
- 修改后首页看板和图表数据实时刷新

#### 3.4.4 删除记账记录

- 在账单列表中直接删除单条记录
- 删除前弹出确认提示
- 删除后首页看板和图表数据实时刷新

---

### 3.5 预算管理

#### 3.5.1 预算设置

- 用户选择月份，输入预算金额
- 支持为不同月份设置不同预算
- 预算金额必须大于 0

#### 3.5.2 预算监控

- 首页实时展示当月预算使用进度
- 预算使用率超过 85% 时给出视觉提醒
- 预算超支时以红色高亮显示

---

### 3.6 数据统计与可视化

#### 3.6.1 月度统计

- 按月汇总总收入、总支出、结余
- 按分类汇总各支出类别的金额与占比
- 计算日均消费金额

#### 3.6.2 年度统计

- 按年汇总总收入、总支出、结余
- 按月展示收支趋势
- 按分类汇总全年各支出类别的金额与占比

---

### 3.7 AI 智能财务分析

#### 3.7.1 月度财务报告

- 用户选择月份，点击"一键生成报告"
- 后端自动聚合该月账单数据，调用大模型生成 Markdown 格式报告
- 报告内容包括：
  - 月度财务概览（总收入、总支出、结余、结余率）
  - 收入与支出结构分析（分类占比、大额消费评估）
  - 消费行为诊断（不理性消费提醒、预算执行情况、消费趋势）
  - 行为经济学洞察（心理账户、锚定效应、损失厌恶等理论分析）
  - 理财建议与下月预算规划
  - 财务健康评分（百分制）

#### 3.7.2 年度财务报告

- 用户选择年份，生成年度财务分析报告
- 报告内容包括：
  - 年度财务总览（全年收入、支出、结余）
  - 月度收支趋势分析
  - 年度分类支出占比（与大学生平均水平对比）
  - 消费习惯变迁分析
  - 大额消费回顾
  - 行为经济学年度洞察
  - 长期理财目标与行为矫正建议

#### 3.7.3 报告缓存与回溯

- 生成的报告自动存入数据库
- 再次查看同一月份/年份时直接读取缓存，无需重新调用大模型
- 用户可手动点击"重新生成"刷新报告

## 4. 非功能性需求

### 4.1 安全性

| 要求 | 实现方式 |
|------|----------|
| 密码安全 | bcrypt 加盐哈希存储，数据库不存明文 |
| 会话隔离 | Token 机制，用户只能访问自身数据 |
| API Key 保护 | 大模型 API Key 通过 `.env` 环境变量配置，不硬编码 |
| 金额精度 | 全链路使用定点数（DECIMAL/Numeric），避免浮点精度丢失 |

### 4.2 性能

- 首页数据加载：通过并行请求（Promise.all）减少等待时间
- AI 报告生成：首次生成 5-20 秒，后续读取缓存即时返回
- 账单列表：前端本地过滤排序，无需重复请求

### 4.3 可用性

- 界面简洁直观，基于 Element Plus 组件库
- 表单校验完善，输入错误有友好提示
- 加载状态有 loading 动画反馈
- 空数据状态有引导提示

### 4.4 可维护性

- 前后端分离，接口契约清晰
- 数据库脚本版本化管理（`initial_schema.sql`）
- 模拟数据脚本支持多用户画像（`generate_mock_data.py`）
- 错误记录文档持续更新（`docs/错误记录.md`）

## 5. 数据流与接口

### 5.1 核心 API 列表

| 接口 | 方法 | 说明 |
|------|------|------|
| `/user/register` | POST | 用户注册 |
| `/user/login` | POST | 用户登录，返回 Token |
| `/category/list/{user_id}` | GET | 获取收支分类列表 |
| `/record/add` | POST | 添加记账记录 |
| `/record/list/{user_id}` | GET | 获取用户全部账单 |
| `/record/today/{user_id}` | GET | 获取当日收支统计 |
| `/budget/save` | POST | 保存月度预算 |
| `/report/ai/{user_id}/{year_month}` | GET | 获取/生成月度 AI 报告 |
| `/report/ai/{user_id}/year/{year}` | GET | 获取/生成年度 AI 报告 |

### 5.2 数据库表结构

| 表名 | 说明 | 核心字段 |
|------|------|----------|
| `user` | 用户表 | user_id, username, password, register_time |
| `category` | 收支分类表 | category_id, category_name, type |
| `bill_record` | 账单记录表 | record_id, amount, date, remark, user_id, category_id |
| `monthly_budget` | 月度预算表 | user_id, year_month, amount |
| `ai_report` | AI 报告表 | report_id, content, year_month, user_id |
