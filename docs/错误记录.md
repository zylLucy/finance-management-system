## 1. MySQL CHECK 约束语法不兼容

### 错误描述
执行 `initial_schema.sql` 时，MySQL 9.6.0 对 CHECK 约束语法报错：
```
ERROR 1064 (42000) at line 40: You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near 'year_month BETWEEN 200001 AND 210012)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4' at line 13
```

### 原因
MySQL 9.x 对 CHECK 约束中的列引用要求使用反引号包裹，且需要额外括号。

### 修复
将 `CHECK (year_month BETWEEN 200001 AND 210012)` 改为 `CHECK ((\`year_month\` BETWEEN 200001 AND 210012))`。

涉及两处：
- `monthly_budget` 表的 `chk_year_month` 约束
- `ai_report` 表的 `chk_report_year_month` 约束

### 状态
✅ 已修复

## 3. SQLAlchemy 2.0 弃用警告

### 错误描述
```
MovedIn20Warning: The ``declarative_base()`` function is now available as sqlalchemy.orm.declarative_base(). (deprecated since: 2.0)
  Base = declarative_base()
```

### 原因
`main.py` 第 28 行使用了 `from sqlalchemy.ext.declarative import declarative_base`，该导入路径在 SQLAlchemy 2.0 中已弃用。

### 修复建议
将 `from sqlalchemy.ext.declarative import declarative_base` 改为 `from sqlalchemy.orm import declarative_base`。

### 状态
⚠️ 已知，不影响运行（警告级别）

## 4. 后端未实现密码哈希，明文存储密码

### 错误描述
后端 `/user/login` 接口直接用 `User.password == password` 做明文字符串比较，`/user/register` 接口直接存储明文密码。mock 数据中密码也是明文 `123456`。这不符合安全规范，密码应以哈希形式存储。

### 原因
后端未引入 bcrypt 或任何密码哈希方案。

### 修复
1. 安装 `bcrypt` 到 `backend/venv`
2. 修改 `login` 接口：先按用户名查用户，再用 `bcrypt.checkpw()` 验证密码哈希
3. 修改 `register` 接口：注册时用 `bcrypt.hashpw()` 对密码做哈希后再存入数据库
4. 更新 `mock_data.sql` 中三个用户的密码为 `123456` 对应的 bcrypt 哈希值
5. 修复 `config.py` 中 `DB_USER` 从 `"zyl"` 改为 `"root"`（MySQL 无 zyl 用户，导致 access denied）

### 状态
✅ 已修复
