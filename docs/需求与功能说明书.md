# 日常记账理财管理系统——需求与功能说明书 (开发者对齐版)

> **项目定位**：数据库课程期末大作业。系统采用前后端分离架构（Vue 3 + FastAPI），以关系型数据库 MySQL 为核心，结合大模型（AI）能力实现智能个人财务分析。
> **协作原则**：契约先行，模块化并发。严格按照本说明书定义的业务边界与数据约束进行开发。

---

## 1. 引言与系统目标

### 1.1 编写目的
本文档详细说明系统的业务流程、功能需求、非功能性技术指标及底层数据映射，用于在前端、后端、数据库、测试各岗组同学之间对齐需求，作为接口开发、系统实现和测试用例设计的唯一依据。

### 1.2 核心优化方向 (极简设计)
为了提高开发效率并优化用户体验，本系统进行了如下关键简化与安全设计：
1. **去邮箱化登录**：取消传统的邮箱验证流程，采用 **“唯一用户名 + 密码”** 的极简登录认证。
2. **两层身份保障**：在数据库层面，用户名被赋予强制唯一约束（`UNIQUE`）；同时在底层设计中保留**用户ID（User ID）**作为自增主键，以保证外键索引的高效性，并为未来“用户改名”留出业务后路。
3. **高频数值精度**：所有涉及财务金额的字段，严格在前端、后端、数据库全链路上采用定点数规范，彻底杜绝浮点数精度丢失问题。

## 2. 核心业务流程设计

### 2.1 用户认证与极简登录流
1. 用户注册：用户输入 `username` 和 `password` ➡️ 后端校验用户名是否已存在 ➡️ 若不存在，利用加盐哈希（如 Bcrypt）对密码加密 ➡️ 将数据持久化写入 `user` 表。
2. 用户登录：用户输入凭证 ➡️ 后端比对哈希值 ➡️ 验证成功后生成 Token ➡️ 前端（Vue3）将 Token 缓存在本地，后续的所有业务请求均需在 Request Header 中携带此 Token。

### 2.2 高频日常记账流
1. 用户在前端点击“记一笔” ➡️ 弹出表单，选择收支类型（收入/支出）、关联分类，输入金额、日期（支持历史日期）及可选备注。
2. 前端通过 Axios 发送 `POST` 请求。
3. 后端校验数据，将其写入 `bill_record` 表，并根据外键 `user_id` 自动关联对应的用户。
4. 后端返回成功响应 ➡️ 前端动态刷新当日收支、月度预算剩余以及图表看板。

### 2.3 AI 智能财务分析流
1. 用户在前端点击“一键生成 AI 财务分析”按钮。
2. 后端拦截请求，自动从 `bill_record` 表中聚合查询出该用户**本月的所有结构化消费数据**（如：餐饮花销占比、总消费额等）。
3. 后端将结构化数据（JSON）注入预设的专业理财 Prompt（提示词）中，调用大模型（DeepSeek/OpenAI）API。
4. 大模型流式返回 Markdown 格式的财务诊断报告。
5. 后端将报告正文存入 `ai_report` 表归档，同时将其返回给前端。
6. 前端渲染 Markdown 报告，用户亦可随时翻阅历史月份的已归档报告，避免重复调用模型接口。

## 3. 功能需求详述 (开发矩阵)

### 3.1 用户管理模块 (User Management)
* **【功能 3.1.1】用户注册与唯一性校验**：用户名全局唯一。若注册时用户名已存在，后端返回 `400` 错误，前端进行友好弹窗提示。密码在传输和存储中必须为加密态。
* **【功能 3.1.2】Token 身份维持**：基于 Token 实现用户会话隔离，确保 A 用户在任何情况下都绝不可能查阅、修改或删除 B 用户的财务数据。
* **【功能 3.1.3】个人月度预算设置**：
    * 用户可设置或修改本月度总预算金额（如 3000.00 元）。
    * **业务硬约束**：每个用户在同一个月份（格式为 `YYYYMM` 的整数，如 `202605`）**仅允许存在一条**预算记录。

### 3.2 收支分类与记账维护模块 (Ledger & CRUD)
* **【功能 3.2.1】收支分类管理**：
    * 系统预设 9 种内置分类（支出类：餐饮、购物、娱乐、交通、学习；收入类：工资、奖学金、生活费、兼职收入）。
    * **参照完整性设计**：删除某一个分类时，由于涉及历史账单的安全，系统默认采取 `RESTRICT`（拒绝删除）策略。若该分类下存在历史账单，必须先将账单归类到其他默认分类，方可删除该分类。
* **【功能 3.2.2】账单流水维护（核心 CRUD）**：
    * **增 (Create)**：支持收支类型切换、金额输入（保留两位小数）、历史日期选择、255字以内的文字备注。
    * **查 (Read)**：支持按记账日期范围筛选、按分类筛选、按备注关键词进行**模糊检索**。
    * **改与删 (Update & Delete)**：用户可直接在列表页修改或删除单条错记流水，数据变更后，首页看板和预算剩余必须实时刷新。

### 3.3 数据统计与可视化模块 (Analytics)
* **【功能 3.3.1】首页核心数据看板**：
    * 实时计算并高亮展示四个指标：`当日总收入`、`当日总支出`、`本月总消费额`、`当月预算剩余百分比`。
* **【功能 3.3.2】ECharts 可视化报表**：
    * **消费结构饼图**：按 `category_id` 聚合，直观展示本月各项支出占总支出的百分比。
    * **收支趋势折线图**：按 `date` 聚合，横轴为本月天数（1-31日），纵轴为金额，展示每日收入与支出的波动曲线。

### 3.4 AI 智能财务顾问模块 (AI Advisor)
* **【功能 3.4.1】定制化财务诊断**：AI 报告内容必须包含：消费占比结构性分析、超支或不理性消费行为提醒、月度理财总结、下月预算开销科学建议。
* **【功能 3.4.2】报告历史回溯**：提供历史月份选择器。前端切换年月时，若数据库中已存在对应报告，则直接读取展现，不再重新向云端发起大模型请求。
